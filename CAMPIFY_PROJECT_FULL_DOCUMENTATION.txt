1. પ્રસ્તાવના અને પ્રોજેક્ટ શું છે? (PROJECT OVERVIEW & WHAT IS CAMPIFY?)
====================================================================================================

"Campify" એ એક અત્યાધુનિક, નેક્સ્ટ-જનરેશન, ફૂલ-સ્ટેક ઓલ-ઇન-વન સોશિયલ નેટવર્કિંગ અને કેમ્પસ કોલેબોરેશન
પ્લેટફોર્મ છે. જે ખાસ કરીને કોલેજ, યુનિવર્સિટી અને વિદ્યાર્થીઓ (Students, Creators & Faculty) ના કેમ્પસ
જીવનને ડિજિટલ, ઇન્ટરેક્ટિવ અને પ્રોડક્ટિવ બનાવવા માટે ડિઝાઇન કરવામાં આવ્યું છે.

સરળ શબ્દોમાં કહીએ તો:
Campify એ સામાન્ય સોશિયલ મીડિયા (જેમ કે Instagram, Threads કે TikTok) ના શ્રેષ્ઠ મનોરંજક અને કમ્યુનિકેશન
ફીચર્સ તેમજ પ્રોફેશનલ/એજ્યુકેશનલ પ્લેટફોર્મ્સ (જેમ કે LinkedIn, Discord કે Coursera) ના એકેડેમિક અને
ટીમ-બિલ્ડિંગ ફીચર્સનું એક શક્તિશાળી ફ્યુઝન (હાઇબ્રિડ) છે.

વિદ્યાર્થીઓ સામાન્ય રીતે Instagram પર રીલ્સ જુએ છે, WhatsApp પર ગ્રૂપ ચેટ કરે છે, LinkedIn પર સ્કિલ્સ શોધે
છે અને હેકાથોન માટે અલગ પોર્ટલ વાપરે છે. Campify આ તમામ સુવિધાઓને એક સિંગલ પ્રીમિયમ એપમાં લાવે છે.

મુખ્ય હાઇલાઇટ્સ:
- Apple-Style Glassmorphism અને Futuristic UI ડિઝાઇન
- ડાર્ક મોડ અને સ્લીક એનિમેશન્સ (Framer Motion અને Tailwind CSS)
- રીયલ-ટાઇમ વેબસોકેટ ચેટ અને લાઇવ નોટિફિકેશન્સ
- 24 કલાકની સ્ટોરીઝ, સ્ટેટસ નોટ્સ અને ઇન્સ્ટન્ટ્સ
- વર્ટિકલ રીલ્સ વિથ ઇન્ટરેક્ટિવ લર્નિંગ ક્વિઝ (Micro-learning)
- હેકાથોન ટીમ પાર્ટનર શોધવા માટે Team Finder
- કોલેજ ઇવેન્ટ્સ, ટેકફેસ્ટ અને વર્કશોપ રજીસ્ટ્રેશન
- ગેમિફિકેશન (XP, લેવલ્સ, ડેઇલી સ્ટ્રીક અને લીડરબોર્ડ)
- ગૂગલ જેમિની (Gemini AI) દ્વારા પાવર્ડ સ્માર્ટ કેપ્શન્સ, હેશટેગ્સ અને કરિયર ગાઇડન્સ
- સંપૂર્ણ રોલ-બેઝ્ડ એડમિન ડેશબોર્ડ અને ઓટોમેટેડ ટોક્સિસિટી સ્કેનર

2. પ્રોજેક્ટ બનાવવાનો હેતુ અને વિઝન (PROBLEM STATEMENT & VISION)
====================================================================================================

[સમસ્યા - The Problem]:
1. કોલેજના વિદ્યાર્થીઓ માટે કોઈ ડેડિકેટેડ કેમ્પસ પ્લેટફોર્મ નથી હોતું જ્યાં તેઓ પોતાના કોલેજ સાથીઓ સાથે
   કનેક્ટ થઈ શકે.
2. Instagram કે Facebook જેવી એપ્સ પર વિદ્યાર્થીઓનો સમય માત્ર ટાઇમપાસમાં વેડફાય છે, કોઈ શૈક્ષણિક લાભ નથી મળતો.
3. હેકાથોન, કોલેજ પ્રોજેક્ટ્સ કે સ્ટાર્ટઅપ માટે યોગ્ય સ્કિલવાળા પાર્ટનર્સ (જેમ કે Frontend Dev, UI Designer,
   AI Engineer) શોધવા ખૂબ અઘરા પડે છે.
4. કેમ્પસમાં કઈ ઇવેન્ટ, સેમિનાર કે સ્પોર્ટ્સ ડે ક્યારે છે તેની માહિતી વોટ્સએપ ગ્રૂપમાં ખોવાઈ જાય છે.
5. વિદ્યાર્થીઓ પાસે પોતાની સ્કિલ્સ અને સર્ટિફિકેટ્સ સાથીઓને બતાવવા માટે સરળ પ્રોફાઇલ નથી હોતી.

[Campify નો ઉકેલ - The Solution]:
Campify આ બધી જ સમસ્યાઓનું સંપૂર્ણ સમાધાન લાવે છે:
- સોશિયલ નેટવર્કિંગ સાથે એજ્યુકેશનલ લર્નિંગનું જોડાણ કર્યું છે.
- વિડિયો રીલ્સ જોતા જોતા વચ્ચે MCQ ક્વિઝ આવે છે જેનાથી નોલેજ વધે છે અને XP પોઇન્ટ્સ મળે છે.
- સ્માર્ટ Team Finder દ્વારા સ્કિલ આધારિત પ્રોજેક્ટ ટીમ બની શકે છે.
- એડવાન્સ્ડ સેફ્ટી અને એડમિન પેનલ દ્વારા કેમ્પસ વાતાવરણ સુરક્ષિત રહે છે.

3. પ્રોજેક્ટ શું કરે છે? - તમામ ફીચર્સ અને મોડ્યુલ્સ (WHAT DOES IT DO?)
====================================================================================================

Campify માં કુલ 13 મુખ્ય મોડ્યુલ્સ (Sub-systems) છે જે નીચે મુજબ વિગતવાર કામ કરે છે:

----------------------------------------------------------------------------------------------------
3.1. હોમ ફીડ અને સોશિયલ કન્ટેન્ટ (Home Feed, Posts, Stories, Notes, Instants)
----------------------------------------------------------------------------------------------------
- Home Feed: યુઝર્સ પોતાના ફોલોઅર્સ અને કેમ્પસના તમામ સ્ટુડન્ટ્સની પોસ્ટ્સ ટાઈમલાઇન પર જોઈ શકે છે.
  પોસ્ટ્સમાં ટેક્સ્ટ, ફોટો, મલ્ટિપલ ઈમેજીસ (Carousel) અને વિડિયો સપોર્ટેડ છે.
- Interactive Reactions: પોસ્ટ પર ડબલ-ટેપથી હાર્ટ લાઈક (Like), નેસ્ટેડ કમેન્ટ્સ (Comments & Replies)
  તેમજ અન્ય યુઝર્સના એકાઉન્ટ પર રિપોસ્ટ (Repost) કરવાની સુવિધા છે.
- Save & Collections: મનપસંદ પોસ્ટ્સને બુકમાર્ક કરીને કસ્ટમ ફોલ્ડર્સ (Collections) માં સાચવી શકાય છે.
- 24-Hour Stories: Instagram ની જેમ 24 કલાકમાં ઓટો-એક્સપાયર થતી ફોટો/વિડિયો સ્ટોરીઝ અપલોડ કરી શકાય છે.
  સ્ટોરી કોણે કોણે જોઈ તેનું રીઅલ-ટાઇમ વ્યુઅર લિસ્ટ (Seen tracking) દેખાય છે. સ્ટોરીમાં બેકગ્રાઉન્ડ સોંગ
  અને ક્લોઝ ફ્રેન્ડ્સ (Close Friends Only) નો પ્રાઇવસી ઓપ્શન પણ મળે છે.
- Instagram Status Notes: પ્રોફાઇલ ઉપર 24 કલાક માટે 60 કેરેક્ટરની નાની નોટ (Note) મૂકી શકાય છે સાથે
  મનપસંદ સોંગ અને ઓડિયો પણ અટેચ થઈ શકે છે.
- Instagram Instants: ત્વરિત કેપ્ચર કરેલા પળો (Flash Moments) કેમ્પસ સાથીઓ સાથે તરત શેર કરી શકાય છે.

----------------------------------------------------------------------------------------------------
3.2. વર્ટિકલ રીલ્સ અને શોર્ટ વિડિયો પ્લેયર (Vertical Reels Engine)
----------------------------------------------------------------------------------------------------
- સ્મૂથ વર્ટિકલ સ્લાઇડિંગ વિડિયો ફીડ (TikTok / Instagram Reels જેવું).
- સાઉન્ડ મ્યુઝિક ઓડિયો પ્લેબેક, લાઈક કાઉન્ટર, શેર અને કમેન્ટ બોક્સ.

4. પ્રોજેક્ટ કઈ રીતે કામ કરે છે? - ટેકનિકલ આર્કિટેક્ચર (HOW DOES IT WORK?)
====================================================================================================

Campify એક મોર્ડન 3-Tier Client-Server Architecture પર કામ કરે છે:

                      ┌──────────────────────────────────────────┐
                      │            CLIENT (BROWSER / PWA)        │
                      │  Next.js 15 App Router + React 19       │
                      │  Zustand Global State + React Query      │
                      └────────────────────┬─────────────────────┘
                                           │
                    HTTP REST API (JSON)   │   WebSockets (Bidirectional)
                    Token: Bearer JWT      │   Events: join_chat, message
                                           │
                                           ▼
                      ┌──────────────────────────────────────────┐
                      │          BACKEND APPLICATION SERVER      │
                      │  Node.js + Express.js + TypeScript       │
                      │  - Security: Helmet, CORS, Rate Limit    │
                      │  - Auth Guards: JWT & RBAC Middleware    │
                      │  - 19 Modular Business Controllers       │
                      │  - Socket.io Real-Time Event Hub         │
                      │  - Automated Toxicity Moderation Scanner │
                      └───────┬───────────────────┬──────────────┘
                              │                   │
         Prisma ORM Queries   │                   │ External API Calls
                              ▼                   ▼
         ┌─────────────────────────┐    ┌─────────────────────────┐
         │     DATABASE LAYER      │    │  THIRD-PARTY SERVICES   │
         │ PostgreSQL / SQLite     │    │ - Google Gemini AI      │
         │ (48 Relational Tables)  │    │ - Cloudinary CDN Media  │
         │ Foreign Keys, Cascades  │    │ - Nodemailer (SMTP OTP) │
         └─────────────────────────┘    └─────────────────────────┘

4.1. ઓવરઓલ સિસ્ટમ વર્કફ્લો
----------------------------------------------------------------------------------------------------
1. ક્લાયન્ટ (યુઝર) બ્રાઉઝરમાં http://localhost:3000 ખોલે છે.
2. Next.js 15 સર્વર અને ક્લાયન્ટ કોમ્પોનન્ટ્સ લોડ થાય છે.
3. યુઝર લોગિન કરે એટલે બેકએન્ડમાંથી JWT Access Token અને Refresh Token જનરેટ થાય છે.
4. આ ટોકન લોકલ સ્ટોરેજ અને Zustand Auth Store માં સેવ થાય છે.
5. હવેથી દરેક HTTP વિનંતી (Request) ના હેડરમાં `Authorization: Bearer <token>` મોકલવામાં આવે છે.
6. તે જ સમયે ફ્રન્ટએન્ડ બેકએન્ડના Socket.io સર્વર સાથે કનેક્ટ થાય છે અને યુઝરની પર્સનલ સોકેટ રૂમમાં જોડાઈ જાય છે.
7. જ્યારે પણ કોઈ ક્રિયા થાય (દા.ત. પોસ્ટ ક્રિએટ, મેસેજ સેન્ડ), ડેટા એક્સપ્રેસ કંટ્રોલર દ્વારા પ્રોસેસ થઈને
   Prisma ORM મારફતે ડેટાબેઝમાં કાયમી સ્ટોર થાય છે અને સોકેટ દ્વારા સંબંધિત યુઝર્સને સેકન્ડના ભાગમાં બ્રોડકાસ્ટ થાય છે.

----------------------------------------------------------------------------------------------------
4.2. ફ્રન્ટએન્ડ કેવી રીતે કામ કરે છે? (Frontend Working)
----------------------------------------------------------------------------------------------------
- Framework: Next.js 15 સાથે React 19 અને App Router આર્કિટેક્ચર વાપરવામાં આવ્યું છે.
- Routing: ફોલ્ડર-બેઝ્ડ રાઉટિંગ છે:
  - `/` -> હોમ ફીડ અને સ્ટોરીઝ સ્લાઇડર (જો લોગિન ન હોય તો પ્રીમિયમ લેન્ડિંગ પેજ)
  - `/auth` -> લોગિન, રજીસ્ટ્રેશન, OTP વેરિફિકેશન અને પાસવર્ડ રીસેટ
  - `/explore` -> ટ્રેન્ડિંગ પોસ્ટ્સ અને સર્ચ ગ્રિડ
  - `/reels` -> વર્ટિકલ ફૂલ-સ્ક્રીન વિડિયો પ્લેયર
  - `/learning` -> શૈક્ષણિક વિડિયોઝ અને MCQ ક્વિઝ પ્રોગ્રેસ
  - `/team-finder` -> પ્રોજેક્ટ ટીમો, રિક્રૂટિંગ ફિલ્ટર્સ અને ઇન્વિટેશન્સ
  - `/events` -> કેમ્પસ ઇવેન્ટ્સ અને રજીસ્ટ્રેશન
  - `/communities` -> સ્ટુડન્ટ ક્લબ્સ, કમ્યુનિટી ડિસ્કશન અને પોલ્સ
  - `/leaderboard` -> XP રેન્કિંગ અને એચિવમેન્ટ્સ
  - `/messages` -> રીઅલ-ટાઇમ ચેટ પેનલ
  - `/notifications` -> રીઅલ-ટાઇમ એલર્ટ હિસ્ટ્રી
  - `/[username]` -> ડાયનેમિક યુઝર પ્રોફાઇલ, સ્કિલ્સ પોર્ટફોલિયો અને પોસ્ટ ગ્રિડ
  - `/admin` -> એડમિન મેટ્રિક્સ અને મોડરેશન કંટ્રોલ
- State Management:
  - Zustand `useAuthStore`: યુઝર લોગિન ક્રેડેન્શિયલ્સ, પ્રોફાઇલ સ્ટેટ સાચવે છે.
  - Zustand `useSocketStore`: વેબસોકેટ કનેક્શન અને ઓનલાઇન સ્ટેટ મેનેજ કરે છે.
  - TanStack React Query: સર્વર ડેટા કેશિંગ, ઓટો-રીફેચ અને ઇન્વેલિડેશન હેન્ડલ કરે છે.
- Styling: Tailwind CSS v4 સાથે કસ્ટમ CSS વેરીયેબલ્સ, ગ્લાસમોર્ફિઝમ ઇફેક્ટ્સ (Backdrop blur) અને
  Framer Motion દ્વારા અત્યંત સ્મૂથ માઇક્રો-એનિમેશન્સ આપેલા છે.

----------------------------------------------------------------------------------------------------
4.3. બેકએન્ડ કેવી રીતે કામ કરે છે? (Backend Working)
----------------------------------------------------------------------------------------------------
- Server Engine: Node.js રનટાઇમ પર Express.js ફ્રેમવર્ક અને TypeScript ભાષામાં કોડિંગ છે.
- Security Layers:
  - `helmet`: HTTP સિક્યોરિટી હેડર્સ સેટ કરે છે.
  - `cors`: ક્રોસ-ઓરિજિન વિનંતીઓને ફક્ત માન્ય ફ્રન્ટએન્ડ ડૉમેઇન પરથી જ એક્સેસ આપે છે.
  - `express-rate-limit`: DDoS અને બ્રુટ-ફોર્સ અટકાવવા 15 મિનિટમાં 200 વિનંતીઓની મર્યાદા રાખે છે.
  - `authenticate` Middleware: JWT ટોકનનું વેરિફિકેશન કરે છે અને `req.user` માં લોગિન યુઝરની વિગત ઇન્જેક્ટ કરે છે.
  - `authorize` Middleware: Role-Based Access Control (RBAC) મુજબ માત્ર 'ADMIN' કે 'MODERATOR' ને જ સંવેદનશીલ રાઉટ્સ આપે છે.
- Modular Controllers: કોડને 19 અલગ અલગ કંટ્રોલર્સમાં વિભાજીત કર્યો છે:
  `auth`, `user`, `post`, `reel`, `story`, `note`, `instant`, `chat`, `notification`, `moderation`,
  `admin`, `ai`, `event`, `community`, `skills`, `team`, `learning`, `gamification`, `upload`.

----------------------------------------------------------------------------------------------------
4.4. ડેટાબેઝ લેયર કેવી રીતે કામ કરે છે? (Prisma ORM)
----------------------------------------------------------------------------------------------------
- ડેટાબેઝ મેનેજમેન્ટ માટે પ્રિઝ્મા ORM (Prisma ORM) નો ઉપયોગ થયો છે.
- ડેવલપમેન્ટમાં SQLite (`kilogram.db`) અને પ્રોડક્શનમાં PostgreSQL વાપરી શકાય છે.
- 48 થી વધુ ટેબલ્સ (Models) વચ્ચે કડક રિલેશનશિપ (Foreign Keys, One-to-Many, Many-to-Many) છે.
- `onDelete: Cascade` નિયમ રાખ્યો છે, જેથી જો યુઝર ડિલીટ થાય તો તેની તમામ પોસ્ટ્સ, લાઇક્સ અને કમેન્ટ્સ
  ડેટાબેઝમાંથી ઓટોમેટિક ક્લીન થઈ જાય છે અને કોઈ ગંદો ડેટા (Orphan rows) રહેતો નથી.

----------------------------------------------------------------------------------------------------
4.5. રિયલ-ટાઇમ વેબસોકેટ્સ કેવી રીતે કામ કરે છે? (Socket.io Architecture)
----------------------------------------------------------------------------------------------------
- HTTP સર્વરની ઉપર `initSocketServer` દ્વારા Socket.io સર્વર શરૂ થાય છે.
- જ્યારે કોઈ ક્લાયન્ટ જોડાય છે, ત્યારે સોકેટ હેન્ડશેક વખતે JWT ટોકન વેરિફાય થાય છે.
- દરેક યુઝરને તેની અંગત રૂમ `user_${userId}` ફાળવવામાં આવે છે.
- જ્યારે વપરાશકર્તા ચેટ ઓપન કરે ત્યારે તે `chat_${chatId}` રૂમમાં જોડાય છે.
- મુખ્ય ઇવેન્ટ્સ:
  - `send_message`: ક્લાયન્ટ મેસેજ મોકલે -> સર્વર ડેટાબેઝમાં મેસેજ સેવ કરે -> તે ચેટ રૂમના તમામ સભ્યોને `receive_message` ઇવેન્ટ ફાયર કરે.
  - `typing`: સામેવાળા યુઝરને "User is typing..." ઇન્ડિકેટર મોકલે.
  - `new_notification`: લાઈક કે કમેન્ટ થાય ત્યારે તુરંત સંબંધિત યુઝરની રૂમમાં નોટિફિકેશન ધકેલે.

----------------------------------------------------------------------------------------------------
4.6. AI ઇન્ટિગ્રેશન પાઇપલાઇન કેવી રીતે કામ કરે છે? (Gemini AI Pipeline)
----------------------------------------------------------------------------------------------------
- `ai.controller.ts` માં ગૂગલ જેમિની 2.5 ફ્લેશ API સાથેનું સીધું કનેક્શન છે.
- જ્યારે યુઝર કેપ્શન, હેશટેગ કે આઇડિયા જનરેટ કરવા વિનંતી કરે છે, ત્યારે સિસ્ટમ ફોર્મેટેડ પ્રોમ્પ્ટ
  તૈયાર કરી જેમિની એન્ડપોઇન્ટ પર મોકલે છે.
- જો નેટવર્ક ન હોય કે API Key સેટ ન હોય, તો સિસ્ટમ ક્રેશ થવાને બદલે સ્માર્ટ લોકલ અલ્ગોરિધમથી
  એન્ગેજિંગ કેપ્શન્સ, હેશટેગ્સ અને વિષયવસ્તુ તરત પરત કરે છે. આનાથી યુઝર એક્સપિરિયન્સ અટકતો નથી.

5. લાઇફસાયકલ અને સ્ટેપ-બાય-સ્ટેપ વર્કફ્લોઝ (STEP-BY-STEP WORKFLOWS)
====================================================================================================

----------------------------------------------------------------------------------------------------
5.1. રજીસ્ટ્રેશન અને OTP વેરિફિકેશન ફ્લો
----------------------------------------------------------------------------------------------------
1. સ્ટુડન્ટ `/auth` પેજ પર જાય છે અને પોતાનું નામ, ઈમેલ, યુઝરનેમ અને પાસવર્ડ દાખલ કરે છે.
2. ફ્રન્ટએન્ડ `POST /api/auth/register` રિક્વેસ્ટ મોકલે છે.
3. બેકએન્ડ ચકાસે છે કે ઈમેલ કે યુઝરનેમ પહેલેથી મોજૂદ નથી ને.
4. પાસવર્ડને `bcryptjs` દ્વારા 10 સોલ્ટ રાઉન્ડ્સ સાથે હેશ (Hash) કરવામાં આવે છે.
5. 6-આંકડાનો સિક્યોર વેરિફિકેશન OTP જનરેટ થાય છે અને Nodemailer દ્વારા યુઝરના ઈમેલ પર મોકલાય છે.
6. યુઝર OTP સ્ક્રીન પર 6-ડિજિટ કોડ એન્ટર કરે છે (`POST /api/auth/verify-otp`).
7. કોડ મેચ થતાં એકાઉન્ટ `verified: true` બને છે અને JWT Access Token સાથે યુઝર સીધો હોમ ફીડ પર રીડાયરેક્ટ થાય છે.

----------------------------------------------------------------------------------------------------
5.2. પોસ્ટ અને મીડિયા અપલોડ લાઇફસાયકલ
----------------------------------------------------------------------------------------------------
1. યુઝર નેવિગેશન બાર પરના "+" બટન પર ક્લિક કરે છે, જેથી `CreatePostModal` ખુલે છે.
2. યુઝર પોતાની કેમ્પસ ઇમેજ કે વિડિયો ફાઇલ સિલેક્ટ કરે છે.
3. ફાઇલ `POST /api/upload` દ્વારા અપલોડ થાય છે (Cloudinary CDN અથવા લોકલ સર્વર ડિરેક્ટરી).
4. યુઝર કેપ્શન લખે છે અથવા "Generate AI Caption" બટન દબાવી સ્માર્ટ કેપ્શન મેળવે છે.
5. "Share Post" પર ક્લિક કરતાં `POST /api/posts` કોલ થાય છે.
6. પોસ્ટ ડેટાબેઝમાં સેવ થાય છે, ટેક્સ્ટમાંથી `#hashtags` અને `@mentions` આપમેળે અલગ તારવવામાં આવે છે.
7. હોમ ફીડ અને તમામ ફોલોઅર્સની ટાઈમલાઇન પર નવી પોસ્ટ તરત દેખાવા લાગે છે.

----------------------------------------------------------------------------------------------------
5.3. લર્નિંગ ક્વિઝ અને XP ગેઇન વર્કફ્લો
----------------------------------------------------------------------------------------------------
1. સ્ટુડન્ટ `/learning` પેજ પર શોર્ટ લર્નિંગ રીલ જુએ છે.
2. રીલ પૂરી થતાં સ્ક્રીન પર MCQ પ્રશ્ન (A, B, C, D ઓપ્શન્સ સાથે) ડિસ્પ્લે થાય છે.
3. સ્ટુડન્ટ ઓપ્શન સિલેક્ટ કરીને સબમિટ કરે છે (`POST /api/learning/quiz/:reelId/submit`).
4. કંટ્રોલર જવાબ ચકાસે છે. જો સાચો જવાબ હોય, તો:
   - `QuizAttempt` માં રેકોર્ડ સેવ થાય છે.
   - સ્ટુડન્ટના `UserGamification` ખાતામાં +25 XP ઉમેરાય છે.
   - જો જરૂરી XP પહોંચી જાય તો યુઝરનું Level (દા.ત. Level 1 -> Level 2) આપોઆપ વધી જાય છે.
   - સ્ક્રીન પર કોન્ફેટી એનિમેશન અને સાચો ખુલાસો (Explanation) દેખાય છે.

----------------------------------------------------------------------------------------------------
5.4. ટીમ ક્રિએશન અને ઇન્વિટેશન મેમ્બર ફ્લો
----------------------------------------------------------------------------------------------------
1. હેકાથોન પાર્ટિસિપન્ટ `/team-finder` પેજ પર "Create Team" પર ક્લિક કરે છે.
2. પ્રોજેક્ટનું નામ (દા.ત. "AI Campus Health Bot"), વર્ણન અને જરૂરી સ્કિલ્સ (દા.ત. "Python, React, NLP") ભરે છે.
3. ડેટાબેઝમાં નવી `Team` બને છે અને ક્રિએટર તેનો લીડર બને છે.
4. લીડર AI Matcher ની મદદથી યોગ્ય સ્ટુડન્ટ્સને સિલેક્ટ કરી "Send Invite" મોકલે છે.
5. આમંત્રિત સ્ટુડન્ટને રીઅલ-ટાઇમ નોટિફિકેશન અને ટીમ કાર્ડ પર "Accept / Decline" બટન મળે છે.
6. Accept કરતાં `TeamMember` તરીકે જોડાણ થાય છે અને બંને વચ્ચે ગ્રૂપ ચેટ એક્ટિવેટ થાય છે.

----------------------------------------------------------------------------------------------------
5.5. રિયલ-ટાઇમ મેસેજિંગ અને સોકેટ ઇવેન્ટ ફ્લો
----------------------------------------------------------------------------------------------------
1. યુઝર `/messages` પેજ પર જઈ કોઈ સાથી વિદ્યાર્થીની ચેટ સિલેક્ટ કરે છે.
2. સોકેટ સર્વર પર `join_chat` ઇવેન્ટ જાય છે અને ક્લાયન્ટ તે રૂમમાં લિસન કરવા લાગે છે.
3. યુઝર મેસેજ ટાઇપ કરીને સેન્ડ દબાવે છે.
4. ફ્રન્ટએન્ડ એક સાથે બે કામ કરે છે:
   - `POST /api/chats/messages/:chatId` કોલ કરી મેસેજ કાયમી ડેટાબેઝમાં સેવ કરે છે.
   - સોકેટ પર `send_message` ઇવેન્ટ બ્રોડકાસ્ટ કરે છે.
5. સામેવાળા યુઝરની સ્ક્રીન પર પેજ રિફ્રેશ કર્યા વગર 0.1 સેકન્ડમાં મેસેજ બબલ દેખાઈ જાય છે અને નોટિફિકેશન સાઉન્ડ વાગે છે.

7. ડેટાબેઝ સ્કીમા અને મોડેલ્સની સંપૂર્ણ વિગત (PRISMA DATA DICTIONARY)
====================================================================================================

Campify ના પ્રિઝ્મા સ્કીમા (`backend/prisma/schema.prisma`) માં કુલ 48 થી વધુ ટેબલ્સ છે.
અહીં સૌથી મહત્વપૂર્ણ મુખ્ય ટેબલ્સનું માળખું દર્શાવેલું છે:

----------------------------------------------------------------------------------------------------
1. Model: User (વિદ્યાર્થી / યુઝર ખાતું)
----------------------------------------------------------------------------------------------------
- `id`                   : String (UUID, Primary Key)
- `email`                : String (Unique) - વિદ્યાર્થીનું ઈમેલ
- `username`             : String (Unique) - અનન્ય યુઝરનેમ હેન્ડલ
- `passwordHash`         : String - સિક્યોર હેશ પાસવર્ડ
- `name`                 : String? - પૂરું નામ
- `role`                 : String (Default: "USER") - USER, MODERATOR, ADMIN
- `status`               : String (Default: "ACTIVE") - ACTIVE, BANNED
- `verified`             : Boolean - બ્લુ વેરિફાઇડ બેજ છે કે નહીં
- `emailVerified`        : Boolean - ઈમેલ OTP વેરિફાય થયેલ છે કે નહીં
- `createdAt / updatedAt`: DateTime - એકાઉન્ટ બન્યા અને બદલાયાનો સમય

----------------------------------------------------------------------------------------------------
2. Model: Profile (વિદ્યાર્થીની વિગતવાર પ્રોફાઇલ)
----------------------------------------------------------------------------------------------------
- `id`        : String (UUID, Primary Key)
- `userId`    : String (Unique, Foreign Key -> User.id, Cascade Delete)
- `bio`       : String? - પોતાના વિશે પરિચય
- `website`   : String? - પર્સનલ પોર્ટફોલિયો કે ગીટહબ લિંક
- `avatarUrl` : String? - પ્રોફાઇલ ફોટો URL
- `coverUrl`  : String? - પ્રોફાઇલ બેનર URL
- `location`  : String? - કોલેજનું નામ અથવા શહેર
- `isPrivate` : Boolean - પ્રાઇવેટ એકાઉન્ટ છે કે પબ્લિક

----------------------------------------------------------------------------------------------------
3. Model: Post (ટાઈમલાઇન પોસ્ટ)
----------------------------------------------------------------------------------------------------
- `id`        : String (UUID, Primary Key)
- `userId`    : String (Foreign Key -> User.id)
- `type`      : String - TEXT, IMAGE, VIDEO, CAROUSEL
- `content`   : String? - પોસ્ટનું કેપ્શન
- `mediaUrls` : String (JSON Array String) - ફોટો/વિડિયોની લિંક્સ
- `hashtags`  : String - અલ્પવિરામ સાથે જોડાયેલા હેશટેગ્સ
- `mentions`  : String - ટેગ કરેલા યુઝર્સ
- `location`  : String? - જીઓ-લોકેશન કે કેમ્પસ સ્પોટ
- `songName`  : String? - પોસ્ટમાં અટેચ કરેલું સોંગ

----------------------------------------------------------------------------------------------------
4. Model: Story (24 કલાકમાં ગાયબ થતી સ્ટોરી)
----------------------------------------------------------------------------------------------------
- `id`             : String (UUID, Primary Key)
- `userId`         : String (Foreign Key -> User.id)
- `mediaUrl`       : String - સ્ટોરી ફોટો કે વિડિયો લિંક
- `type`           : String (IMAGE / VIDEO)
- `isCloseFriends` : Boolean - ફક્ત અંગત મિત્રો માટે છે કે બધા માટે
- `expiresAt`      : DateTime - એક્સપાયરી તારીખ (24 કલાક બાદ)
- `songName`       : String? - બેકગ્રાઉન્ડ મ્યુઝિક

----------------------------------------------------------------------------------------------------
5. Model: Reel & ReelQuiz (વિડિયો રીલ્સ અને ક્વિઝ)
----------------------------------------------------------------------------------------------------
- Reel:
  - `id`       : String (UUID, Primary Key)
  - `userId`   : String (Foreign Key -> User.id)
  - `videoUrl` : String - વર્ટિકલ વિડિયો ફાઇલ લિંક
  - `caption`  : String? - વિડિયો કેપ્શન
- ReelQuiz:
  - `id`           : String (UUID, Primary Key)
  - `reelId`       : String (Unique, Foreign Key -> Reel.id)
  - `question`     : String - MCQ પ્રશ્ન
  - `optionA..D`   : String - 4 અલગ અલગ વિકલ્પો
  - `correctAnswer`: String (A, B, C અથવા D)
  - `explanation`  : String? - સાચા જવાબની સમજૂતી

----------------------------------------------------------------------------------------------------
6. Model: Team & TeamMember (પ્રોજેક્ટ ટીમ મેકિંગ)
----------------------------------------------------------------------------------------------------
- Team:
  - `id`          : String (UUID, Primary Key)
  - `name`        : String - ટીમ કે પ્રોજેક્ટનું નામ
  - `description` : String - પ્રોજેક્ટનો ઉદ્દેશ
  - `lookingFor`  : String - કયો રોલ જોઈએ છે (Developer, Designer)
  - `skillsNeeded`: String - જરૂરી સ્કિલ્સ
  - `creatorId`   : String - ટીમ બનાવનાર લીડર
- TeamMember:
  - `teamId` : String (Foreign Key -> Team.id)
  - `userId` : String (Foreign Key -> User.id)
  - `role`   : String (CREATOR, ADMIN, MEMBER)

----------------------------------------------------------------------------------------------------
7. Model: Community, Event & Poll (કેમ્પસ ક્લબ્સ અને ઇવેન્ટ્સ)
----------------------------------------------------------------------------------------------------
- Community: ક્લબનું નામ, ડિસ્ક્રિપ્શન, પ્રાઇવેટ/પબ્લિક, લોગો અને બેનર.
- CommunityEvent: ઇવેન્ટનું નામ, તારીખ, સ્થળ અને એટેન્ડી લિસ્ટ.
- CommunityPoll: પ્રશ્ન અને ઓપ્શન્સ, જેમાં વિદ્યાર્થીઓ લાઈવ વોટ આપે છે.

----------------------------------------------------------------------------------------------------
8. Model: Chat & Message (રીઅલ-ટાઇમ મેસેજિંગ)
----------------------------------------------------------------------------------------------------
- Chat:
  - `id`      : String (UUID, Primary Key)
  - `isGroup` : Boolean - સિંગલ DM છે કે ગ્રૂપ
  - `name`    : String? - ગ્રૂપનું નામ
- Message:
  - `id`       : String (UUID, Primary Key)
  - `chatId`   : String (Foreign Key -> Chat.id)
  - `senderId` : String (Foreign Key -> User.id)
  - `type`     : String (TEXT, IMAGE, VIDEO, VOICE)
  - `content`  : String? - ટેક્સ્ટ મેસેજ
  - `mediaUrl` : String? - અટેચમેન્ટ
  - `readBy`   : String (JSON Array) - કયા કયા સભ્યોએ મેસેજ વાંચ્યો

----------------------------------------------------------------------------------------------------
9. Model: UserGamification & Achievements (ગેમિફિકેશન)
----------------------------------------------------------------------------------------------------
- `userId`      : String (Unique, Foreign Key -> User.id)
- `xpPoints`    : Int (Default: 0) - કુલ કમાયેલા એક્સપી પોઇન્ટ્સ
- `level`       : Int (Default: 1) - યુઝરનું લેવલ
- `dailyStreak` : Int (Default: 0) - સતત કેટલા દિવસથી એક્ટિવ છે
- `streakFrozen`: Boolean - સ્ટ્રીક ફ્રીઝ થયેલ છે કે નહીં

8. બેકએન્ડ REST API એન્ડપોઇન્ટ્સની સંપૂર્ણ યાદી (API DIRECTORY)
====================================================================================================

બેઝ URL: `http://localhost:5000/api` (Local) અથવા લાઈવ સર્વર URL.

[1. ઓથેન્ટિકેશન (Authentication)]:
- POST   /api/auth/register           : નવું એકાઉન્ટ રજીસ્ટર કરવું અને ઈમેલ OTP મોકલવો
- POST   /api/auth/verify-otp         : 6-આંકડાનો OTP ચકાસી એકાઉન્ટ સક્રિય કરવું
- POST   /api/auth/resend-otp         : નવો OTP ફરીથી મોકલવો
- POST   /api/auth/login              : ઈમેલ/યુઝરનેમ અને પાસવર્ડથી લોગિન કરવું
- POST   /api/auth/refresh            : એક્સપાયર થયેલ JWT એક્સેસ ટોકન રીફ્રેશ કરવો
- POST   /api/auth/google             : ગૂગલ સિંગલ સાઇન-ઓન (SSO)
- POST   /api/auth/forgot-password    : પાસવર્ડ ભૂલી ગયા હોય ત્યારે રીસેટ લિંક/OTP મેળવવો
- POST   /api/auth/reset-password     : નવો પાસવર્ડ સેટ કરવો
- POST   /api/auth/change-password    : લોગિન થયેલ યુઝર દ્વારા પાસવર્ડ બદલવો

[2. યુઝર પ્રોફાઇલ (User & Social Profile)]:
- GET    /api/users/profile/:username : યુઝરની પબ્લિક પ્રોફાઇલ, બાયો, આંકડા અને પોસ્ટ્સ મેળવવી
- PUT    /api/users/profile           : બાયો, નામ, વેબસાઇટ, અવતાર અને પ્રાઇવસી અપડેટ કરવી
- GET    /api/users/suggested         : ફોલો કરવા માટે સજેસ્ટેડ વિદ્યાર્થીઓનું લિસ્ટ
- GET    /api/users/search?q=:query   : નામ કે યુઝરનેમથી સર્ચ કરવું
- POST   /api/users/follow/:id        : વિદ્યાર્થીને ફોલો કરવો
- DELETE /api/users/unfollow/:id      : અનફોલો કરવો
- GET    /api/users/followers/:id     : ફોલોઅર્સનું લિસ્ટ
- GET    /api/users/following/:id     : ફોલોઇંગનું લિસ્ટ
- POST   /api/users/block             : યુઝરને બ્લોક કરવો
- POST   /api/users/mute              : યુઝરને મ્યુટ કરવો
- GET    /api/users/close-friends     : ક્લોઝ ફ્રેન્ડ્સ લિસ્ટ મેળવવું
- POST   /api/users/close-friends     : ક્લોઝ ફ્રેન્ડ્સ લિસ્ટ અપડેટ કરવું

[3. પોસ્ટ્સ અને ફીડ (Posts & Interactions)]:
- POST   /api/upload                  : ઈમેજ/વિડિયો ફાઇલ સર્વર પર અપલોડ કરવી
- GET    /api/posts/feed              : હોમ ફીડની પોસ્ટ્સ પેજીનેશન સાથે ફેચ કરવી
- POST   /api/posts                   : નવી પોસ્ટ ક્રિએટ કરવી
- POST   /api/posts/like/:postId      : પોસ્ટ લાઈક કરવી
- DELETE /api/posts/unlike/:postId    : લાઈક હટાવવી
- POST   /api/posts/comment/:postId   : પોસ્ટ પર કમેન્ટ કરવી
- GET    /api/posts/comment/:postId   : પોસ્ટની તમામ કમેન્ટ્સ અને રીપ્લાય જોવા
- POST   /api/posts/save/:postId      : પોસ્ટ બુકમાર્ક / સેવ કરવી
- DELETE /api/posts/:postId           : પોતાની પોસ્ટ ડિલીટ કરવી
- POST   /api/posts/repost/:postId    : પોસ્ટને પોતાના પ્રોફાઇલ પર રીપોસ્ટ કરવી

10. પ્રોજેક્ટ રન અને સેટઅપ કરવાની ગાઇડ (INSTALLATION & HOW TO RUN)
====================================================================================================

પ્રોજેક્ટને તમારા કમ્પ્યુટર પર લોકલ ચલાવવા માટે નીચેના સ્ટેપ્સ ફોલો કરો:

[પૂર્વજરૂરિયાતો (Prerequisites)]:
- Node.js (v18 અથવા v20+ ઇન્સ્ટોલ કરેલું હોવું જોઈએ)
- npm અથવા yarn
- Git

----------------------------------------------------------------------------------------------------
પગલું ૧: બેકએન્ડ સર્વર સેટઅપ કરો (Backend Setup)
----------------------------------------------------------------------------------------------------
1. ટર્મિનલ / કમાન્ડ પ્રોમ્પ્ટ ખોલો અને `backend` ફોલ્ડરમાં જાઓ:
   cd backend

2. જરૂરી તમામ પેકેજીસ ઇન્સ્ટોલ કરો:
   npm install

3. ડેટાબેઝ માઇગ્રેશન ચલાવી ટેબલ્સ બનાવો:
   npx prisma migrate dev --name init

4. ડેમો ડેટા અને ટેસ્ટિંગ એકાઉન્ટ્સ ડેટાબેઝમાં લોડ કરો:
   npx prisma db seed

5. બેકએન્ડ ડેવલપમેન્ટ સર્વર શરૂ કરો:
   npm run dev

   -> સર્વર પોર્ટ 5000 અથવા 5001 પર સફળતાપૂર્વક શરૂ થઈ જશે!
   -> "Campify Backend Server Running on Port 5000" મેસેજ દેખાશે.

----------------------------------------------------------------------------------------------------
પગલું ૨: ફ્રન્ટએન્ડ ક્લાયન્ટ સેટઅપ કરો (Frontend Setup)
----------------------------------------------------------------------------------------------------
1. બીજું નવું ટર્મિનલ ખોલો અને `frontend` ફોલ્ડરમાં જાઓ:
   cd frontend

2. ફ્રન્ટએન્ડ પેકેજીસ ઇન્સ્ટોલ કરો:
   npm install

3. ફ્રન્ટએન્ડ સર્વર શરૂ કરો:
   npm run dev

4. બ્રાઉઝરમાં નીચેની લિંક ખોલો:
   http://localhost:3000

   -> Campify નું સુંદર હોમ પેજ અથવા લેન્ડિંગ પેજ ખૂલી જશે!
